# Agent Note: 全局资讯推荐轮播

Status: implemented

## Problem

用户需要在使用个人工具其他页面时，于右下角直接发现资讯，并能展开、收起和轮播阅读。既有资讯页面需要主动进入，无法提供这一入口；Skills 操作通知已占用右下角，独立固定定位会造成遮挡。

## Decision

在 App 挂载全局推荐框，默认收起，展开后显示一篇标题、摘要、来源、日期及预览按钮，保留上一条、下一条、暂停 / 播放和全部资讯入口。状态保留至本次应用关闭，切换页面不重置。每 8 秒轮播；悬停、焦点进入、窗口隐藏或阅读弹窗时暂停，减少动态效果偏好下默认不自动播放。手动切换重新计时，不抢焦点、不自动播报每一轮内容。

复用资讯缓存、语言和翻译动作，只翻译当前展开阅读的一条。推荐从最近 30 天有日期的条目中按来源轮选最多八条，避免单个高频发布源刷屏；无近期资讯时明确提示，不把旧消息伪装为最新。未知 / 无效日期及超出既有五分钟时钟容差的未来日期不入选。刷新保留当前 URL，移除 / 暂停来源后重新选择。沿用资讯纯文本预览组件，点击先预览，之后可打开原网页。

右下角使用一个布局容器：操作通知通过 React portal 进入上方通知区，推荐框居下，统一视口约束；Modal 和命令面板位于该容器之上。不新增依赖、后端接口或采集计划，不要求用户配置推荐参数。

历史审计：[资讯覆盖与中文阅读](2026-10-18-agent-news-chinese-coverage.md)与[原资讯模块](2026-10-18-agent-news.md)部分相关，沿用其缓存和翻译边界；[Skills 启停](2026-10-13-skills-activation.md)部分相关，通知内容和动作保持，仅调整挂载布局；其他笔记与轮播交互无关。

## Alternatives considered

- 直接按时间取八条：能突出刚发生的更新，但 GitHub 高频版本会占满推荐，采用每个来源先选一条再补齐的轮选。
- 每个浮层独立 fixed 并提高 z-index：局部实现最少，但通知和推荐会互相覆盖，采用共享角落布局保持两者可操作。
- 引入轮播库或 LLM 排名：支持丰富动效和个性化，但八条纯文本资讯可用原生按钮和定时器完成，不增加运行和维护成本。

## Verification

- 单元测试验证近期来源轮选、高频来源不挤掉其他来源、失败来源缓存可用、最多八条、排除旧消息 / 无效日期 / 停用来源，以及空数据无虚构内容。
- Playwright 通过受控时钟验证八秒循环、悬停与焦点暂停、手动暂停恢复、后台停止、预览及收起停播；实际点击验证跨页面展开状态、方向键、Escape、预览后外跳、刷新新增条目仍保留当前 URL。
- 中文沿用、单条禁用切换、空列表、1440×900 / 853×480 / 375×812 视口边界和浅深主题截图纳入界面测试；Skills 隔离 fixture 测试确认真实操作通知进入共享通知区并位于推荐框上方。
- 沿用 `npm test`、`npm run test:ui`、`npm run build:desktop` 和 `npm run verify-notes` 检查。未修改 Rust 核心；资讯采集和翻译网络行为沿用已有验证。

## Consequences

其他页面具备近期资讯入口，采集、缓存、翻译和预览实现保持共用。此处“推荐”是近期多来源精选，不推断个人兴趣或真实性；依赖原来源日期和网络，翻译失败保留原文并给出提示。浮层展开后占用并覆盖其下方屏幕区域，因此默认收起、支持 Escape 收起并限制尺寸；需要操作底层内容时可收起。通知较多时角落区域可滚动。展开状态仅保留在本次应用生命周期，重启后恢复收起；若以后增加永久偏好，应并入正式设置。
