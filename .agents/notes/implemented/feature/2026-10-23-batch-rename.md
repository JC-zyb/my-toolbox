# Agent Note: 批量改名规则与可撤销执行

Status: implemented

## Problem

现有改名只支持文件主名的字面替换与前后缀，没有过滤、编号、选择与撤销。覆盖检查把大小写改名和批内占位误判为冲突，执行没有识别预览后替换的文件，逐个直接改名也不能安全处理循环依赖。

## Decision

Rust 独立 rename 模块管理规则、唯一预览和最近一批撤销，桌面命令只传结构化请求、预览 ID 和选择的来源路径。规则支持普通/正则替换、首个/全部匹配、大小写敏感、主名/完整名/扩展名、前后缀、大小写转换，以及含 {name}/{ext}/{n} 的命名模板。编号按筛选后的自然名称顺序固定，取消选择不会让其他文件编号跳变；扩展名筛选和隐藏文件选项在扫描时生效。单目录普通文件，不递归、不处理链接、不覆盖批外目标。

预览保留目录身份、文件身份及长度/修改时间。选项变更立即作废界面预览，异步旧结果不重新激活。执行重新检查来源及实际目录占用；冲突检查只允许所选、确实移走的来源腾出目标。所有来源先转唯一临时名，再发布目标；失败逆序分阶段恢复并报告无法恢复的具体路径，临时文件丢失也明确标记回滚未完成。系统不覆盖的文件移动用于正常执行与恢复。最近一批成功映射保留在内存中，撤销也复核身份、占用并经过确认，不宣称支持退出/崩溃恢复。预览有效期 15 分钟。桌面命令在阻塞线程持锁串行操作，避免扫描或执行阻塞窗口。

不把创建时间用作文件戳：Windows 名称复用的交换/撤销测试中，它在改名后发生变化，文件身份、长度与修改时间仍保持一致。执行与撤销复用原始文件戳，不在移动后重新采信外部写入的版本。Windows 文件身份使用卷序列号与文件索引，Unix 使用设备与 inode；不跟随重新解析点取得身份。

- [renamer](https://github.com/75lb/renamer)：参考 dry-run 和规则组合，不引入可执行 JavaScript 插件。

当场检索活跃笔记：与[工作台架构](../architecture/2026-10-12-local-workbench.md)部分重叠，沿用服务端预览、不覆盖与失败报告约束，补充本模块规则及撤销；本地工具与 Skills 笔记的事务属于其他资源，不吸收也不归档。

## Alternatives considered

- 直接调用 F2 可立即获得成熟规则与撤销，但增加二进制部署、CLI 版本和错误解析契约；复用现有 Rust 服务，学习设计而不嵌入 CLI。
- 逐个按依赖拓扑排序改名通常只需一次移动，但循环及大小写仍需特判，失败恢复更难证明；统一两阶段处理。
- 冲突自动补号能减少操作，但会改变用户确认的名称且掩盖规则错误；显示所有冲突，允许取消选择后重新计算。
- 持久化撤销和崩溃日志可跨重启恢复，但需要日志生命周期和文件外部变化协调；当前明确只保存最近一批的会话撤销，不承诺崩溃原子性。

## Testing

Rust 测试覆盖规则、自然排序编号、非法名称、全批重复、批外占用、选择依赖、文件变化、目录变化、过期/重放、两阶段回滚及回滚未完成报告、大小写/循环及撤销。前端单测验证所选行的依赖和全部冲突标记；UI 通过真实隔离 Rust 桥验证规则、选择、确认、文件变化拒绝执行、原名称被占用拒绝撤销、筛选分页、主题与窄窗，直接断言临时文件的名称和内容。测试桥仅允许新建系统临时子目录，不接入生产应用。

2026-10-23 Windows 本机验收：前端 19 项、Rust 97 项（含改名 14 项）、Edge UI 31 项（含改名 4 项）全部通过；前端构建、嵌入资源的 debug 桌面构建和笔记门禁通过。改名截图检查浅色、深色及 375px 窄窗；原生目录选择框和其他操作系统未在此轮 UI 自动化中验收。

## Consequences

组合规则和选择预览覆盖常见整理需求；统一两阶段移动简化循环与大小写处理，代价是每个文件需要两次移动。Windows 使用不带覆盖标志的 MoveFileExW，Unix 用不覆盖的 hard-link/unlink，因此不支持硬链接的 Unix 文件系统会显式失败，没有降级为可能覆盖目标的 rename。新增 regex 是已在锁文件中的传递依赖，不增加外部运行程序。

两阶段执行并非文件系统事务；应用崩溃可能留下临时名，运行中外部进程仍可能竞争路径。文件身份与元数据避免常见过期执行，不把它们称为内容哈希；刻意保持长度和修改时间的内容变化不保证识别。大量文件预览按页显示，预览不会加载文件内容。当前本机验证 Windows；Unix 路径仍需对应平台 CI 实跑。
