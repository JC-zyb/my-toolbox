# Agent Note: Skills 卡片与真实 Agent 启停

Status: implemented

## Problem

矩阵和分发预览暴露太多实现信息，无法通过详情直接启停。Codex 全局直接发现中央库，移走兼容链接并不能禁用技能。

## Decision

采用卡片与主内容详情，统一展示 `enabled` 状态；日常勾选即时执行，冲突、外部实体目录和首次导入确认。Claude Code、DSH 通过入口启停，全局 Codex 使用官方 `[[skills.config]]` 对实际 `SKILL.md` 路径逐项设置 `enabled`，缺省视为启用，操作成功提示重启。项目 Codex 使用安装入口，并读取对应路径的禁用配置。配置文件以 `toml_edit` 更新并保留其他内容、注释和格式；重复矛盾配置、解析失败及预览后外部变化均拒绝写入。配置发布与中央导入、Agent 入口共用批量事务及逆序恢复。

卡片右上角总开关对当前工作空间全部可管理 Agent 执行一次性启停，右下角图标仍能独立操作。前端按 Skill-Agent 局部乐观更新，不等待全量扫描；普通受管理入口使用轻量启停命令，冲突和外部内容回退到预览确认。所有会改变技能的操作通过页面右下角 Toast 报告处理中、成功、失败或需要确认状态；失败必须回滚本地乐观状态。

启停的发现和预览只读取请求指定的 Skill 目录，不调用全库 `scan`。一次预览共用已发现的行，应用继续使用来源、目标、父目录、Codex 配置指纹及文件系统/SQLite 回滚；响应只包含请求涉及的 Agent，避免一个响应覆盖其他并行操作。全库发现保留在进入页面和手动扫描。前端按技能串行提交，处理中仍接受点击并合并为各 Agent 的最后意图，卡片与详情共用这一队列；确认或失败只恢复本次目标，其他技能的乐观状态不受影响。普通短操作延迟显示处理中 Toast，避免快速操作闪出提示；成功通知在后台确认后出现。

与[矩阵决策](2026-10-13-skills-matrix.md)部分重叠：继续来源扫描、批量指纹和备份；矩阵作为内部数据，日常视图采用卡片；兼容清理仍单独保留，不冒充启停。Markdown 渲染禁用原始 HTML，源码仍可查看。卡片和详情都读取同一矩阵状态。

## Alternatives considered

- 所有 Agent 都用链接可统一实现，但 `.agents` 中央库被 Codex 直接扫描，删除兼容链接无效；不改既有中央路径，使用官方配置。
- 每次勾选显示预览可完整核对，但用户要求普通操作即时执行，仅冲突和外部内容显示确认。
- 每次操作后重新扫描整个矩阵可以保证状态最新，但会造成约两秒的可感知停顿；采用后端状态增量和焦点/进入页面时的校验，保留预览指纹校验作为安全边界。
- 重用全量批量预览的最强理由是可以不新增写入分支、完整保留事务保护；但旧快速接口在三个 Agent 操作中构建七次全矩阵，隔离测试中 100 个技能耗时约 21 秒。保留同一事务执行器，将发现范围收窄为当前技能并复用行，比复制一套直接写入代码更容易维护。
- 仅在详情页显示操作结果可以减少全局 UI，但卡片操作没有就近反馈；采用统一右下角 Toast，并让详情页复用同一通知流。
- 继续源码预览无需依赖，但用户要求参考图的正文展示，加入 `react-markdown` 并禁止原始 HTML。

## Consequences

全局 Codex 的状态表示已写入配置，运行中的会话要重启才会采用新值。项目入口状态与全局配置分别展示；用户能直接从卡片看到三种 Agent 的状态，只有多选和高级信息才显示批量及兼容细节。

## Verification

Rust 测试覆盖 Codex 配置格式和注释保留、同名旧库文档同步禁用、配置变化与矛盾项拒绝，以及配置先发布而后续 Agent 安装失败时文件和 SQLite 回滚。Playwright 使用隔离 Rust fixture，覆盖卡片状态、详情即时启停、Markdown/源码/来源、命令面板进入详情、批量启停、Agent 独有技能导入和外部目录确认。执行构建、前端测试、Rust 测试、UI 测试、笔记校验和桌面打包。

补充隔离测试证明快速启停不登记无关技能、不触发全库扫描；单元测试以可控异步请求验证连续点击的最后意图、失败局部回滚、不同技能并行及过期响应保护。性能复测只使用临时目录，比较 2/40/100 个技能的同一请求。

## Risks

Codex 设置需重启后生效；项目入口关闭不代表全局技能禁用。文件系统异常尝试回滚，进程突然退出需用备份恢复。开发验证仅使用隔离目录。
